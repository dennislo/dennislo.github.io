# Dependency sweep — 2026-11-12

## Result

The direct application dependencies are already current, so no runtime package
upgrade is proposed. A clean Gatsby build did reveal an invalid transitive AJV
placement in the lockfile: `ajv-keywords@5.1.0` requires AJV 8, but resolved the
hoisted AJV 6 used by legacy tooling. Adding AJV 8 as an explicit development
dependency makes npm install the compatible version at the package root.

The sweep adds `ajv` 8.20.0 and `ajv-keywords` 5.1.0 as paired direct
development dependencies. This does not change browser runtime code; it makes
the existing `schema-utils@4.8.3` toolchain resolve its declared AJV 8 peer
dependency while npm nests the legacy AJV 6/keywords 3 pair together.

All direct development dependencies are also current according to npm.

## Risk assessment

There is no application migration. The main risk is install-time dependency
resolution: legacy ESLint and Gatsby loaders still require AJV 6, so the
lockfile retains nested AJV 6 copies while AJV 8 is installed at the root.
Validation must include a clean install and production build to prove both
generations resolve correctly.

The local default environment uses Node 26, while Gatsby 5.16 declares support
for Node versions `>=18 <26`; validation therefore uses Node 20.19.0. Node 26
failures should be treated as an environment compatibility issue rather than a
dependency regression.
